# 参加者（follower）作業

道案内をたどる側。全体像は [overview.md](./overview.md) を参照。

## 開発環境

- iPhone を想定。Web アプリ（PWA）として実装し、iOS アプリは作らない。

## UI（画面の配置）

- **入口画面**: 配布 URL を開くと直接道案内画面に着く設計。URL のパスに道案内 ID を含める（例: `/r/abc123`）。QR はスマホ標準カメラで読む前提なので、アプリ内の QR リーダーは作らない。デモ用に残す場合は ID を入力して遷移するだけの軽い画面にする。
- **道案内表示画面**: 現在ステップの写真、矢印、目印の文章、次の目印までの距離を表示する。「次へ」「前へ」ボタンで手動でも進める。
- **通り過ぎ警告**: 道案内表示画面の上に重ねて表示する。

## フロントエンド

### データ取得
- **写真列 JSON の取得**: 画面を開いたときにバックエンドから 1 回だけ取得する。以降の処理はすべて端末内で完結させる。
- **画像の先読み**: 全ステップの画像を最初に読み込み、歩行中の電波状況に左右されないようにする。

### 端末内で保持するデータ
- 写真列 JSON（各ステップの緯度経度、曲がる方向、次ステップまでの距離）
- 経路のポリライン
- 現在のステップ番号
- 直近の現在地と精度

### 位置追跡と判定
- **位置追跡**: Geolocation の `watchPosition` で現在地を取り続ける。
- **到達判定**: 次の目印までの距離が 15〜20m 以内になったら自動で次ステップへ進める。
- **通り過ぎ判定**: 次の目印までの距離が一度縮んだあと、数回連続で広がったら警告を出す。GPS の揺れによる誤検知を避けるため、1 回の増加では反応しない。
- **経路外れ判定**: ポリラインからの最短距離が 30〜50m を超えたら「道を間違えた可能性」を表示する。
- **精度の扱い**: `accuracy` が大きいときは判定を保留するか、しきい値を広げる。

## バックエンド

- **道案内取得 API**: 公開済みの道案内を ID で返す。返す内容はステップの配列と経路のポリライン。各ステップに画像 URL、緯度経度、目印の文章、曲がる方向、次ステップまでの距離を持たせる。距離と方向は作成時に計算済みで、参加者側では再計算しない。
- **画像配信**: ストレージの公開 URL をそのまま返す。
- 参加者側からバックエンドへの送信は行わない（統計機能はスコープ外）。

## ツール選定

| 用途 | ツール |
|---|---|
| Web アプリ | Vite + React + TypeScript。PWA 化（vite-plugin-pwa）でホーム画面追加・全画面表示 |
| 位置情報 | Geolocation API。距離・方位・ポリラインとの距離計算は turf.js |
| QR | アプリ内には実装しない。スマホ標準カメラに任せる |
| ホスティング | Vercel または Cloudflare Pages |
