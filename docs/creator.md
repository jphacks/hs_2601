# 作る人（creator）作業

道案内を作成・公開する側。全体像と API の境界は [overview.md](./overview.md) を参照。

## 開発環境

- iPhone を想定。Web アプリ（PWA）として実装し、iOS アプリは作らない。

## UI（画面の配置）

### 画面遷移
```
ホーム
├─ 道を作る
│   ├─ 出発地・目的地の入力
│   ├─ カメラで写真を撮る ⇄ 撮った写真の一覧（参照・削除・追加）
│   ├─ 作成中（ローディング）
│   └─ 作成結果の確認
└─ 作った道を公開する
    ├─ 道の一覧（チェックで選択）
    ├─ 道の詳細表示
    └─ 公開完了（URL・QR 表示）
```

### 各画面
- **ホーム（定常状態）**: 「道を作る」「作った道を公開する」の 2 ボタン。
- **出発地・目的地の入力**: 「道を作る」の最初に置く。テキスト入力で十分。
- **カメラで写真を撮る**: 撮影ボタンを押すとカメラアプリが起動する。撮影後は写真一覧に戻る。
- **撮った写真の一覧**: サムネイル表示、削除、追加撮影のボタン。並び順は経路側で位置から決めるので、手動の並び替えは不要。
- **作成中（ローディング）**: 作成ボタンを押した後、バックエンドの処理完了まで待つ画面。
- **作成結果の確認**: 生成された写真列をプレビュー表示する。参加者側の道案内表示画面と同じ見た目にする。やり直す場合は写真一覧に戻る。
- **道の一覧（チェックで選択）**: 自分が作った道案内を一覧表示し、チェックボックスで選ぶ。
- **道の詳細表示**: 作成結果の確認画面と共通化する。
- **公開完了（URL・QR 表示）**: 公開ボタンを押した後、参加者に渡す URL と QR を表示する。

## フロントエンド

### 入力・撮影
- **出発地・目的地の入力**: 文字列として保持し、作成時にバックエンドへ送る。ジオコーディングはバックエンドに任せる。
- **撮影**: `<input type="file" accept="image/*" capture="environment">` でカメラを起動する。File を受け取った瞬間に Geolocation の `getCurrentPosition` で座標と精度を取り、写真と座標をペアで保持する。
- **写真の保持**: ページを閉じても残るよう IndexedDB に保存する。メモリだけだとリロードで消える。
- **写真一覧**: IndexedDB から読み出してサムネイル表示。削除は IndexedDB から消す。

### 作成
- **作成実行**: 出発地・目的地・写真と座標の一覧を FormData で送信し、ジョブ ID を受け取る。
- **作成中の待機**: ステータス API を数秒おきにポーリングし、完了したら結果確認画面へ遷移する。失敗時はエラー表示と写真一覧への戻りボタン。
- **作成結果の確認**: 詳細取得 API で写真列 JSON を取り、参加者側と同じ表示コンポーネントで描画する。

### 公開
- **道の一覧**: 一覧取得 API で自分の道案内を取り、チェックで選択する。
- **公開**: 公開 API を呼び、返ってきた公開 URL を表示する。QR はフロント側で URL から生成する。

### 作成者の識別
- ログイン機能は作らない。初回アクセス時にランダムな作成者 ID を生成して localStorage に保存し、作成・一覧取得時に送る。

## バックエンド

### API
- **作成受付 API**: 出発地・目的地・写真と座標・作成者 ID を受け取り、写真をストレージに保存し、下書き状態でレコードを作る。作成ジョブを非同期で開始し、ジョブ ID を返す。
- **ステータス取得 API**: ジョブ ID を受け取り、作成中・完了・失敗を返す。
- **一覧取得 API**: 作成者 ID を受け取り、その作成者の道案内一覧を返す。
- **詳細取得 API**: 道案内 ID を受け取り、写真列 JSON を返す。作る人の確認画面と参加者の表示画面で共用する。参加者向けには公開済みのものだけ返す。
- **公開 API**: 道案内 ID を受け取り、ステータスを公開済みに変えて公開 URL を返す。

### 作成ジョブの処理
1. **ジオコーディング**: 出発地・目的地の文字列を Geocoding API で緯度経度に変換する。
2. **経路計算**: Routes API に出発地・目的地と写真の座標を経由地として渡し、徒歩経路を取得する。経由地の順序最適化を有効にする。
3. **曲がり角の抽出**: 経路のステップ情報から曲がる地点を取り出す。作成者が写真を撮った地点は必ずステップに含める。
4. **Street View 画像の取得**: 作成者の写真がない曲がり角について、Metadata API で画像の有無を確認し、Static API で進行方向を向いた画像を取得する。
5. **目印の抽出（VLM）**: 各ステップの画像を Claude API に渡し、「何を目印に、どちらへ曲がるか」の短い文章を生成する。VLM が使えない場合は「○m 先を右」のような経路情報だけの文章にフォールバックする。
6. **曲がる方向の計算と矢印描画**: 前後のステップの方位差から左折・右折・直進を判定し、Pillow で画像に矢印を重ねる。矢印付き画像をストレージに保存する。
7. **距離計算**: 各ステップから次ステップまでの距離を経路から算出する。
8. **写真列 JSON の組み立て**: ステップ配列と経路のポリラインをまとめて DB に保存し、ステータスを完了にする。

### 画像保存
- 作成者の写真と矢印付き画像をストレージに保存し、公開 URL を発行する。

## ツール選定

| 用途 | ツール |
|---|---|
| Web アプリ | 参加者側と同じ Vite + React + TypeScript。1 リポジトリでパスを分ける |
| カメラ | `<input capture>` 方式。独自シャッター UI は作らない |
| 位置情報 | Geolocation API |
| 写真の保持 | IndexedDB（idb-keyval） |
| バックエンド | FastAPI（Python）。Pillow（画像処理）、httpx（HTTP）、polyline（デコード）、geopy（方位計算）。非同期ジョブは BackgroundTasks |
| 外部 API | Google Geocoding API、Routes API、Street View Static API と Metadata API、Claude API（画像入力） |
| DB・ストレージ | Supabase（Postgres + Storage）。ハッカソン規模なら SQLite + ローカルファイルでも可 |
| QR 生成 | qrcode.react（フロント側で URL から生成） |
| 実機確認 | Cloudflare Tunnel または ngrok で開発 PC を HTTPS 公開し、iPhone から接続 |
