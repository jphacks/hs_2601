## 1. 概要

### 1.1 困っている人

#### 道案内を作る人（作る人）
- 看板を立てたり、目的地までの途中に人を立たせたりするのは面倒
- 一方で、Google Map 等のリンクだけを渡すのも味気ない（？）

#### その会場に行きたい人（参加者）
- 「駅 → 会場」の道のりなので、もっとシンプルに案内してほしい
- 看板等が実際に見えているような、直感的な移動がしたい

### 1.2 解決したいこと

| 立場 | 解決したいこと |
|---|---|
| 作る人 | 中継点（駅など）から **1 回道を歩くだけ** で、目印・曲がり角などの簡単な道案内を作れる |
| 参加者 | 目印・曲がる方角だけを **画面に単純に表示** してくれればよい |

### 1.3 何が欲しいか

#### 作る人
- **操作をどれだけ省略できるか** を最重視
- 自分でその地点の写真を撮る → そのままバックエンドで交差点同士をつなぐ
  - 撮影はアプリ内で行う（アルバムから参照した写真は位置情報が取れないことがある）
- どこを目印にするか・どこを曲がるかはすべてバックエンドが出す
  - 実際に撮った写真 + どこに曲がるか
- 作る人が撮るのは **Street View 等では分かりにくい、ややこしいポイントだけ**
  - → それらを通る経路を計算し、他の交差点の目印は Google Street View（+ VLM で目印抽出）で補完
- 写真撮影時点の位置情報 → 目印になる交差点・位置を教えてくれる
- VLM で「何を目印にすればいいか」を抽出

#### 参加者
- （同様に）操作を省略したい
- 各写真の場所 → 次にどこをどう曲がるかだけを教えてくれる
- 会場に行くまでの **最低限** だけでよい（付随情報は不要）

### 1.4 あればうれしい機能
- 他の誰かが作ったデータを溜めておく（人気の場所をキャッシュ）
  - 誰かのデータを流用できるはず
- 最小限の動作に加えて、画像を順に表示していく
  - あとどのくらい直進か
  - その画像の場所に着いたらどちらに行くか
  - 間違っていたら教えてくれる 等
- どこで迷ったか等の統計（バックエンド）
  - **今回のスコープ外**

## 2. 必要なコンポーネント

### 2.1 作る人側
1. ややこしい箇所・その目印・どこに入るか等を **先に写真に撮る + 位置情報を取得**
   - アプリ内撮影とし、撮影と同時に Geolocation API で座標を取る
2. 「移動元 → 移動先」を入力として、上記の地点を **すべて通る経路** を算出
3. 各交差点について Street View の写真を切り出す
   - ① VLM に入力して目印を出してもらう
   - ② 曲がる方向を計算し、描画
   - VLM が利用できなければ、経路情報だけの文章にフォールバック
4. 各写真を連結して **道の計画（写真列）** を出力
5. 道の計画を URL で公開（Web アプリ前提）

### 2.2 参加者側
1. 道の計画を表示
2. 写真列を表示（目印の写真・右左折・次までの距離）
   - 距離・方向は作成時に計算済みの値を使い、参加者側では再計算しない
3. 通り過ぎの検知

## 3. 開発環境

- 参加者・作る人ともに **iPhone を想定**
- Mac がないため iOS アプリは作らず、**Web アプリ（PWA）として実装**
- HTTPS 必須（カメラ・位置情報の制約）。実機確認は Cloudflare Tunnel または ngrok

---

## 4. フロントとバックの境界（先に決める API）

分担して同時に進めるため、最初に次の 5 本の API の形を決める。

| API | 入力 | 出力 |
|---|---|---|
| 作成受付 | 出発地・目的地・写真と座標・作成者 ID | ジョブ ID |
| ステータス取得 | ジョブ ID | 作成中 / 完了 / 失敗 |
| 一覧取得 | 作成者 ID | 道案内の一覧 |
| 詳細取得 | 道案内 ID | 写真列 JSON（作る人の確認画面と参加者の表示画面で共用） |
| 公開 | 道案内 ID | 公開 URL |

写真列 JSON の中身:
- ステップの配列（各ステップ: 画像 URL、緯度経度、目印の文章、曲がる方向、次ステップまでの距離）
- 経路のポリライン
